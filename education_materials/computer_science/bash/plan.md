## 3.2. Страницы модуля

## Страница 18. `18-files.html`

Тема: проверки файлов и директорий.

### Теория

Ключевые проверки:

```bash
[[ -e "$path" ]]
[[ -f "$file" ]]
[[ -d "$dir" ]]
[[ -r "$file" ]]
[[ -w "$file" ]]
[[ -x "$file" ]]
```

### Что объяснить

- `-e` — путь существует;
- `-f` — обычный файл;
- `-d` — директория;
- `-r` — можно читать;
- `-w` — можно писать;
- `-x` — можно выполнять.

### Блок «Глубже»

Объяснить, что проверка существования и проверка типа — разные вещи.

Пример:

```bash
if [[ -e "$path" ]]; then
    echo "Путь существует"
fi

if [[ -f "$path" ]]; then
    echo "Это файл"
fi
```

### Типичные ошибки

- проверять файл без кавычек;
- путать `-e` и `-f`;
- считать, что директория — это тоже файл;
- не проверять права перед чтением.

### Упражнения 3+2

Простые:

1. Написать проверку, что `file` — обычный файл.
2. Написать проверку, что `dir` — директория.
3. Написать проверку, что `file` можно читать.

Сложнее:

4. Написать `if`, который выводит `OK`, если файл существует.
5. Написать проверку: путь существует и доступен для чтения.

### Задача на подумать

Написать фрагмент, который принимает путь `$1` и сообщает:

- не существует;
- файл;
- директория.

## Страница 19. `19-read-lines.html`

Тема: чтение файла построчно.

### Теория

Главный безопасный шаблон:

```bash
while IFS= read -r line; do
    echo "$line"
done < "$file"
```

### Что объяснить

- почему нужен `IFS=`;
- почему нужен `read -r`;
- зачем перенаправление `< "$file"`;
- почему нельзя читать файл через `for line in $(cat file)`.

### Блок «Глубже»

Объяснить, что строки файла могут содержать:

- пробелы;
- табуляции;
- обратные слэши;
- пустые строки.

Безопасный шаблон должен сохранить строку как есть.

### Типичные ошибки

Плохо:

```bash
for line in $(cat "$file"); do
    echo "$line"
done
```

Почему плохо:

- ломает строки по пробелам;
- теряет структуру файла;
- создаёт лишний процесс `cat`.

### Упражнения 3+2

Простые:

1. Написать начало цикла `while IFS= read -r line`.
2. Написать перенаправление файла в цикл.
3. Безопасно вывести строку.

Сложнее:

4. Добавить счётчик строк.
5. Пропустить пустые строки.

### Задача на подумать

Написать фрагмент, который читает файл и выводит только непустые строки.

## Страница 20. `20-find.html`

Тема: поиск файлов через `find`.

### Теория

Ключевые команды:

```bash
find . -type f
find . -type d
find . -type f -name "*.txt"
find "$dir" -type f -name "*.log"
```

### Что объяснить

- стартовая директория;
- `-type f`;
- `-type d`;
- `-name`;
- кавычки вокруг шаблона `"*.txt"`;
- почему shell не должен раскрывать `*.txt` раньше `find`.

### Блок «Глубже»

Разница:

```bash
find . -name *.txt
```

и

```bash
find . -name "*.txt"
```

Во втором случае шаблон получает сама команда `find`.

### Типичные ошибки

- забыть кавычки вокруг `*.txt`;
- искать от `.` не понимая текущую директорию;
- использовать `find /` без необходимости;
- удалять через `find ... -delete` без dry-run.

### Упражнения 3+2

Простые:

1. Найти все файлы.
2. Найти все директории.
3. Найти все `.txt`.

Сложнее:

5. Найти файлы старше 7 дней.

### Задача на подумать

## Страница 21. `21-safe-delete.html`

Тема: безопасное удаление и dry-run.

### Теория

Опасные команды:

```bash
rm -rf "$dir"
find "$dir" -type f -delete
```

Безопасный подход:

```bash
echo rm -rf "$dir"
```

или:

```bash
DRY_RUN=1
```

### Что объяснить

- почему удаление необратимо;
- почему важно проверять переменные;
- почему нужен dry-run;
- почему нельзя удалять пустой путь.

### Шаблон проверки

```bash
: "${TARGET:?Нужен TARGET}"

if [[ ! -d "$TARGET" ]]; then
    echo "Нет такой директории: $TARGET" >&2
    exit 1
fi
```

### Типичные ошибки

- `rm -rf $DIR` без кавычек;
- удаление без проверки существования;
- удаление без dry-run;
- отсутствие логирования.

### Упражнения 3+2

Простые:

1. Написать обязательную проверку `TARGET`.
2. Проверить, что `TARGET` — директория.
3. Написать dry-run через `echo`.

Сложнее:

4. Добавить подтверждение `yes/no`.
5. Добавить режим `--dry-run`.

### Задача на подумать

Написать безопасный фрагмент удаления директории только после проверки и подтверждения.

## Страница 26. `26-shift.html`

### Теория


- `shift 2` используется для флага со значением.

- пишет ошибки в `stderr`;
- логирует действия;
- умеет dry-run;

- имеет тестовые сценарии;

Финальный ориентир:

```bash
#!/bin/bash
set -euo pipefail

usage() {
    cat <<'EOF'
Usage:
  tool.sh --file PATH [--verbose] [--dry-run]
EOF
}

log_info() {
    local MSG="$1"
    echo "[INFO] $MSG"
}

log_error() {
    local MSG="$1"
    echo "[ERROR] $MSG" >&2
}

main() {
    # parse args
    # validate input
    # run logic
    # log result
    :
}

main "$@"
```
