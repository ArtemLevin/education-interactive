01

Структура скрипта и права доступа

shebang · chmod · запуск
⌄

Shebang

#!/bin/bash
  • Должен быть первой строкой файла без пробелов или пустых строк до него.
  • #!/bin/bash явно указывает на интерпретатор Bash.
  • #!/bin/sh может ссылаться на dash, где отсутствуют Bash-специфичные возможности: [[ ]], массивы, pipefail.

Права на выполнение

chmod +x script.sh   # Безопасно: добавляет бит исполнения
# chmod 777 script.sh  # ОПАСНО: даёт чтение/запись/выполнение всем

Запуск: ./script.sh ищет скрипт в текущей директории. Команда bash script.sh запускает файл как дочерний процесс и игнорирует права +x.

02

Строгий режим: set -euo pipefail

errexit · nounset · pipefail
⌄ 
set -euo pipefail
  • -e / errexit: скрипт прерывается при первом ненулевом коде возврата. Исключения: команды в if, while, ||, &&.
  • -u / nounset: ошибка при обращении к неопределённой переменной. Спасает от опечаток вроде $VRA вместо $VAR.
  • -o pipefail: статус пайплайна равен статусу последней упавшей команды, а не последней команды в цепочке.
💡 Нюанс. Без pipefail команда false | true вернёт 0, хотя false упала. С pipefail вернёт 1, и set -e остановит скрипт.
03

Переменные, аргументы и подстановка

VAR · $@ · $# · модификаторы
⌄

Присваивание и доступ

VAR="значение"      # БЕЗ пробелов вокруг =
echo "$VAR"         # Правильно
echo $VAR           # Опасно при пробелах

Позиционные параметры

  • $1, $2, ... — аргументы при запуске.
  • $@ — все аргументы как отдельные слова; при "$@" сохраняет пробелы.
  • $* — все аргументы как одна строка.
  • $# — количество аргументов.
  • $? — код возврата последней команды; сбрасывается после каждой новой команды.
  • $0 — имя скрипта.

Модификаторы подстановки

${1:-GET}      # Если $1 пуст или не задан, подставить "GET"
${1:?Ошибка!}  # Если $1 пуст, вывести ошибку и прервать скрипт
${#VAR}        # Длина строки в переменной
${VAR:0:5}     # Срез первых 5 символов
04

Кавычки: правила выживания

double quotes · single quotes · command substitution
⌄
  • "..." — двойные кавычки: подстановка переменных $VAR и команд $(cmd). Защищают пробелы и спецсимволы.
  • '...' — одинарные кавычки: литерал. Ничего не подставляется. Удобны для регулярных выражений и сырых строк.
  • $(cmd) лучше, чем `cmd`: поддерживает вложенность и читается аккуратнее.
⚠️ Золотое правило. Всегда оборачивайте переменные в кавычки: "$var". Исключения возможны, но привычка к кавычкам резко снижает риск ошибок с пробелами и пустыми значениями.
05

Условия и современные тесты [[ ... ]]

if · elif · regex · операторы
⌄ 
if [[ -z "$VAR" ]]; then
    echo "Пусто"
elif [[ "$VAR" == "POST" ]]; then
    echo "Метод POST"
else
    echo "Другое значение"
fi
  • [[ ... ]] — встроенный синтаксис Bash. Не требует экранирования <, >, &&, ||.
  • [ ... ] / test — POSIX-совместимый, но менее удобный и более хрупкий синтаксис.
  • Операторы: -z, -n, -eq, -ne, -gt, -ge, -lt, -le, ==, !=.
✅ Совет. Внутри [[ ]] логические операторы пишутся как &&, ||, !. Не используйте -a, -o: это устаревший стиль.
06

Циклы и безопасный перебор

"$@" · nullglob · glob-паттерны
⌄

Перебор аргументов

for ITEM in "$@"; do
    echo "Обрабатываю: $ITEM"
done
💡 Нюанс. in "$@" — стандарт для передачи аргументов скрипта в цикл. Кавычки гарантируют, что строки с пробелами не разобьются на части.

Перебор файлов

shopt -s nullglob  # Если *.txt нет, цикл не выполнится
for f in *.txt; do
    echo "Файл: $f"
done
shopt -u nullglob  # Вернуть стандартное поведение

Без nullglob при отсутствии файлов переменная получит литерал "*.txt", что часто приводит к ошибке.

07

Функции, область видимости и local

function scope · local · return
⌄ 
my_func() {
    local STATUS="$1"    # local обязателен для внутренних переменных
    local MSG="$2"
    echo "[$STATUS] $MSG"
    return 0             # Код возврата 0-255
}
  • В Bash переменные глобальны по умолчанию. Без local функция может перезаписать переменную из основного скрипта.
  • Аргументы функции $1, $@, $# работают изолированно от аргументов скрипта.
  • return возвращает только код статуса. Для текста используйте echo и захват: RESULT=$(my_func).
08

Обработка ошибок и потоки вывода

stdout · stderr · exit codes
⌄

Стандартные потоки

  • stdout / 1 — нормальный вывод. Перенаправление: >, >>.
  • stderr / 2 — ошибки. Перенаправление: 2>, 2>>.
  • Разделение критично для логирования, CI/CD и мониторинга: ./script.sh > out.log 2> err.log.

Паттерн || для мягкой обработки

risky_command || {
    echo "❌ Ошибка выполнения" >&2
    exit 1
}
💡 Нюанс. set -e автоматически отключается для команд, связанных через ||, && или находящихся в if/while. Это позволяет обрабатывать ошибки явно.
09

Чек-лист лучших практик

короткая памятка перед практикой
⌄
  1. Первая строка: #!/bin/bash, сразу под ней: set -euo pipefail.
  2. Все переменные в кавычках: "$var".
  3. В функциях все внутренние переменные объявляйте через local.
  4. Условия: [[ "$var" == "value" ]] вместо хрупких [ ].
  5. Проверка аргументов: ${1:?msg} или ${1:-default}.
  6. Циклы по аргументам: for x in "$@".
  7. Ошибки пишите в stderr: echo "err" >&2.
  8. Завершайте скрипт явно: exit 0.
  9. Форматируйте логи: [INFO], [ERROR], эмодзи или теги.
  10. Тестируйте в песочнице. Используйте echo перед destructive-командами.
