0ВВЕДЕНИЕ

Данное пособие систематизирует теорию и лучшие практики первых двух модулей обучения. Фокус сделан на БЕЗОПАСНОСТИ, ЧИТАЕМОСТИ и СОВРЕМЕННЫХ СТАНДАРТАХ BASH 4+/5. Все примеры предполагают запуск в изолированной директории (например, mkdir -p ~/bash_sandbox).

НИКОГДА НЕ ТЕСТИРУЙТЕ СКРИПТЫ С rm, curl С ЗАПИСЬЮ В ФАЙЛ ИЛИ sudo В СИСТЕМНЫХ ПАПКАХ. ИСПОЛЬЗУЙТЕ echo ДЛЯ DRY-RUN ДО ПОЛНОЙ ОТЛАДКИ.

1СТРУКТУРА СКРИПТА И ПРАВА ДОСТУПА

Каждый исполняемый Bash-скрипт начинается с двух обязательных элементов.

1.1 Shebang

#!/bin/bash
  • Должен быть ПЕРВОЙ СТРОКОЙ файла без пробелов или пустых строк до него.
  • #!/bin/bash явно указывает на интерпретатор Bash. #!/bin/sh может ссылаться на dash (в Debian/Ubuntu), где отсутствуют Bash-специфичные фичи ([[ ]], массивы, pipefail).

1.2 Права на выполнение

chmod +x script.sh # БЕЗОПАСНО: добавляет бит исполнения # chmod 777 script.sh # ОПАСНО: даёт право на чтение/запись/выполнение ВСЕМ

Запуск: ./script.sh (ищет в текущей директории) или bash script.sh (запускает как дочерний процесс, игнорируя права +x).

2СТРОГИЙ РЕЖИМ: SET -EUO PIPEFAIL

set -euo pipefail
ФЛАГ ЧТО ДЕЛАЕТ ПРИМЕР
-e Скрипт прерывается при первом ненулевом коде возврата false → скрипт остановится
-u Ошибка при обращении к неопределённой переменной $VRA вместо $VAR → ошибка
-o pipefail Статус пайплайна = статус последней УПАВШЕЙ команды false | true → вернёт 1
ПРИМЕР БЕЗ pipefail: false | true вернёт 0 (успех), хотя false упал. С pipefail вернёт 1, и set -e остановит скрипт.

Исключения: set -e автоматически отключается для команд в if, while, ||, &&.

3ПЕРЕМЕННЫЕ, АРГУМЕНТЫ И ПОДСТАНОВКА

3.1 Присваивание и доступ

VAR="значение" # БЕЗ пробелов вокруг = echo "$VAR" # ПРАВИЛЬНО echo $VAR # ОПАСНО при пробелах

3.2 Позиционные параметры

  • $1, $2, ... — аргументы при запуске.
  • $@ — все аргументы как отдельные слова (сохраняет пробелы при "$@").
  • $* — все аргументы как одна строка (разделяется первым символом IFS, обычно пробелом).
  • $# — количество аргументов.
  • $? — код возврата последней команды (сбрасывается после каждой новой команды).
  • $0 — имя скрипта.

3.3 Модификаторы подстановки

${1:-GET} # Если $1 пуст или не задан, подставить "GET" ${1:?Ошибка!} # Если $1 пуст, вывести ошибку и прервать скрипт ${#VAR} # Длина строки в переменной ${VAR:0:5} # Срез первых 5 символов

4КАВЫЧКИ: ПРАВИЛА ВЫЖИВАНИЯ

ТИП ОПИСАНИЕ ПРИМЕР
"..." Подстановка переменных $VAR и команд $(cmd). Защищает пробелы. echo "$HOME"
'...' ЛИТЕРАЛ. Ничего не подставляется. echo '$HOME' → $HOME
$(cmd) Командная подстановка (современный стандарт). DATE=$(date)
`cmd` Устаревшая командная подстановка. DATE=`date` (не рекомендуется)
ЗОЛОТОЕ ПРАВИЛО: ВСЕГДА ОБВОРАЧИВАЙТЕ ПЕРЕМЕННЫЕ В КАВЫЧКИ: "$var". ИСКЛЮЧЕНИЯ: АРИФМЕТИКА (( $var + 1 )), УСЛОВИЯ [[ $var -eq 0 ]].

5УСЛОВИЯ И СОВРЕМЕННЫЕ ТЕСТЫ [[ ... ]]

if [[ -z "$VAR" ]]; then echo "ПУСТО" elif [[ "$VAR" == "POST" ]]; then echo "МЕТОД POST" else echo "ДРУГОЕ ЗНАЧЕНИЕ" fi

5.1 [[ ... ]] vs [ ... ]

  • [[ ... ]] — встроенный синтаксис Bash. Не требует экранирования <, >, &&, ||. Работает с ==, !=, =~ (regex).
  • [ ... ] (или test) — устаревший POSIX-совместимый синтаксис. Требует экранирования, менее безопасен при пустых переменных.

5.2 Операторы сравнения

ОПЕРАТОР ОПИСАНИЕ ПРИМЕР
-z Строка пуста [[ -z "$VAR" ]]
-n Строка не пуста [[ -n "$VAR" ]]
-eq, -ne Числовое равно / не равно [[ $A -eq $B ]]
-gt, -ge, -lt, -le Больше / больше или равно / меньше / меньше или равно [[ $A -ge 400 ]]
==, != Строковое равно / не равно [[ "$A" == "POST" ]]
ВНУТРИ [[ ]] ЛОГИЧЕСКИЕ ОПЕРАТОРЫ ПИШУТСЯ КАК &&, ||, !. НЕ ИСПОЛЬЗУЙТЕ -a, -o (DEPRECATED В POSIX).

6ЦИКЛЫ И БЕЗОПАСНЫЙ ПЕРЕБОР

6.1 Перебор аргументов

for ITEM in "$@"; do echo "ОБРАБАТЫВАЮ: $ITEM" done
in "$@" — СТАНДАРТ ДЛЯ ПЕРЕДАЧИ АРГУМЕНТОВ СКРИПТА В ЦИКЛ. КАВЫЧКИ ГАРАНТИРУЮТ, ЧТО СТРОКИ С ПРОБЕЛАМИ НЕ РАЗОБЬЮТСЯ НА ЧАСТИ. in $* ИЛИ in $@ (БЕЗ КАВЫЧЕК) РАЗОБЬЁТ "file name.txt" НА ДВА ЭЛЕМЕНТА.

6.2 Перебор файлов (опасность пустой директории)

shopt -s nullglob # Если *.txt нет, цикл не выполнится for f in *.txt; do echo "ФАЙЛ: $f" done shopt -u nullglob # ВЕРНУТЬ СТАНДАРТНОЕ ПОВЕДЕНИЕ

Без nullglob при отсутствии файлов переменная получит литерал "*.txt", что приведёт к ошибке.

7ФУНКЦИИ, ОБЛАСТЬ ВИДИМОСТИ И LOCAL

my_func() { local STATUS="$1" # local ОБЯЗАТЕЛЕН для всех внутренних переменных local MSG="$2" echo "[$STATUS] $MSG" return 0 # Код возврата 0-255 }
  • В Bash переменные ГЛОБАЛЬНЫ ПО УМОЛЧАНИЮ. Без local функция перезапишет переменную с тем же именем в основном скрипте.
  • Аргументы функции: $1, $@, $# работают изолированно от аргументов скрипта.
  • Возврат данных: return возвращает КОД СТАТУСА (число 0-255). Для возврата текста используйте echo "data" и захват: RESULT=$(my_func).

8ОБРАБОТКА ОШИБОК И ПОТОКИ ВЫВОДА

8.1 Стандартные потоки

ПОТОК ОПИСАНИЕ ПЕРЕНАПРАВЛЕНИЕ
stdout (1) Нормальный вывод >, >>
stderr (2) Ошибки 2>, 2>>

Разделение критично для логирования, CI/CD и мониторинга: ./script.sh > out.log 2> err.log.

8.2 Паттерн || для мягкой обработки

risky_command || { echo "❌ ОШИБКА ВЫПОЛНЕНИЯ" >&2 exit 1 }
set -e АВТОМАТИЧЕСКИ ОТКЛЮЧАЕТСЯ ДЛЯ КОМАНД, СВЯЗАННЫХ ЧЕРЕЗ ||, && ИЛИ НАХОДЯЩИХСЯ В if/while. ЭТО ПОЗВОЛЯЕТ ОБРАБАТЫВАТЬ ОШИБКИ БЕЗ ВРЕМЕННОГО set +e.

9. ЧЕК-ЛИСТ ЛУЧШИХ ПРАКТИК (МОДУЛИ 1–2)

  1. Первая строка: #!/bin/bash, сразу под ней: set -euo pipefail.
  2. Все переменные в кавычках: "$var".
  3. В функциях все внутренние переменные: local.
  4. Условия: [[ "$var" == "value" ]] вместо [ ].
  5. Проверка аргументов: ${1:?msg} или ${1:-default}.
  6. Циклы по аргументам: for x in "$@".
  7. Ошибки пишите в stderr: echo "err" >&2.
  8. Завершайте скрипт явно: exit 0 (для оркестраторов и systemd).
  9. Форматируйте логи: префиксы [INFO], [ERROR], эмодзи или теги для grep/awk.
  10. Тестируйте в песочнице. Используйте echo перед destructive-командами.
